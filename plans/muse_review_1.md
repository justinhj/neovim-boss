Reviewed. This is genuinely impressive work — a full Neovim msgpack-RPC client, MCP server, socket auto-discovery, and build-time API codegen, all in Zig with tests. The layered architecture doc in the README matches the actual code, which is rarer than it should be. A few real issues below, ordered by severity.
Bugs
Freeing a string literal (UB/crash), src/discovery.zig:94. canonicalizePath returns the static "/" when the path trims to empty. Every caller frees the result based on pointer comparison (e.g. line 117, 458), so nb detect / or any target dir of "/" will allocator.free("/"). Fix: always return an owned dupe, even for root.
Zombie child processes, src/transport.zig:157. close() calls c.kill(io) on a spawned nvim --embed but never waits on it, so every torn-down child transport leaves a zombie until nb exits. For a long-running MCP server using nb mcp child, those accumulate. Add a wait/reap after kill.
Leaked seen-map keys, src/discovery.zig:290. In scanDirRecursive, saved is duped as a key into seen but that path never frees keys (seen.deinit doesn't free keys, and these strings aren't in candidates). Small and CLI-lifetime-bounded, but it's a leak all the same. The env-var path (line 335) is fine since the same pointer lands in candidates.
Design smells
Pointer-identity ownership is fragile. The canon.ptr != full_path.ptr idiom (lines 117, 294, 340, 358, 458) works today only because you audited every return path of canonicalizePath. One future early-return of a borrowed slice and you get a double-free or a leak. An explicit OwnedOrBorrowed union or an always-dupe convention would be cheaper to reason about.
Security rationale is inconsistent. The README proudly rejects :!cmd shell execution "due to security risks" — but exec_lua hands the agent arbitrary Lua, and os.execute("...") is one call away. The threat model is really "the MCP client is fully trusted," which is fine, but the :!cmd section implies a sandbox that doesn't exist. I'd reframe it as a deliberate trust boundary.
localhost → 127.0.0.1 rewrite in connectTcp silently breaks IPv6-only setups. Prefer resolving the hostname as-is and only special-case on failure.
Nits
build.zig still carries all the zig init tutorial comments ("This creates a module, which represents a collection of source files..."). 200+ lines of it. Trim to what this project actually does.
All five examples plus codegen get installArtifact'd into zig-out/bin on every build — probably fine, but worth a conscious choice.
msgPackToJson coerces .binary to a JSON string without UTF-8 validation; a binary-heavy response (e.g. reading a non-text buffer) can emit invalid JSON to the MCP client.
MCP_PROTOCOL_VERSION = "2024-11-05" is two spec revisions behind current. Works with most clients via version negotiation, but worth bumping.
update-api-info shells out via sh -c with a redirect — fine on macOS/Linux, dead on Windows if you ever care.
What's strong: the re-entrant reverse-RPC handling in client.zig is correct and well-tested (the socketpair tests are exactly the right approach), the discovery scoring with canonicalized paths is thoughtful, embedding the Lua scripts with @embedFile is the right call, and the tool-pruning philosophy in the README shows real product judgment — 9 tools instead of 40 is why this will actually get used.
One caveat: no Zig toolchain on this machine, so this is a static review — I didn't run zig build test. The test suite looks thorough, but the "/" free bug above is exactly the kind of thing test "discovery: scorePathMatch" would catch if you added a "/" case.
